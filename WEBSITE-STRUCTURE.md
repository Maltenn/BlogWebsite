# BlogWebsite — Structure Reference

Personal blog / homepage for **Marc** ("Malten"), rebuilt (July 2026) as a full **Windows-98-style desktop experience** with a MySpace/GeoCities aesthetic: draggable windows, taskbar + Start menu, games, sparkle cursor, 88x31 badge marquee, on a pastel-purple background with animated stars. Static frontend + two optional local Node/Express backends.

## Big picture

```
Static HTML/CSS/JS on GitHub Pages (works fully standalone — the API is an optional enhancement)
  └── worker/  (Cloudflare Worker + D1, free plan) → https://ourspace-api.ourspace-api.workers.dev
        GET/POST /messages = the live guestbook · GET /top-tracks = malten's real Spotify top songs (10-min cache, cron-warmed)
```

The page degrades gracefully when the API is unreachable: guestbook falls back to localStorage; the Spotify list falls back to the last result cached in localStorage, then to a snapshot baked into `apps.js`. `msgserver/` and `spotifyserver/` are the OLD localhost backends the Worker replaced (Oct 23, 2026) — `spotifyserver/` is still the way to mint a new Spotify refresh token (`/login`), see `worker/README.md`.

## Hosting (live since October 23, 2026)

- **Repo:** https://github.com/Maltenn/BlogWebsite (public; only `main` is pushed — `old-master-DO-NOT-PUSH` stays local, see Gotchas).
- **Live site:** https://maltenn.github.io/BlogWebsite/ — GitHub Pages, deployed from branch `main`, folder `/` (root), classic (legacy) build. There is no build step of our own: every push to `main` redeploys in about a minute (`gh api repos/Maltenn/BlogWebsite/pages/builds/latest` shows the status). Everything uses relative paths, so the `/BlogWebsite/` prefix doesn't matter; `404.html` handles nested missing paths itself (see its row below).
- **Custom domain: `ourspace.page`** (bought at Porkbun, Oct 23 2026). Set in repo Settings → Pages; GitHub committed the root `CNAME` file (`ourspace.page`) itself — leave that file alone. `.page` is on the browser HSTS preload list, so it only ever loads over HTTPS: the site is unreachable until GitHub's DNS check passes and it issues the certificate. DNS at Porkbun (first delete the parking A records and the `www` CNAME to `pixie.porkbun.com`): apex A `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153` + AAAA `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153` (or one ALIAS → `maltenn.github.io`); `www` CNAME → `maltenn.github.io`. Certificate issued and Enforce HTTPS on since Oct 23, 2026 (`https_enforced: true`; `http://` and `www` 301 to `https://ourspace.page/`); the github.io URL redirects to the domain too. If GitHub ever sits on a certificate for more than an hour, removing and re-adding the custom domain (`PUT repos/Maltenn/BlogWebsite/pages` with `cname: null`, then with `cname=ourspace.page`) re-triggers issuance — that is what finally worked here.
- **API: `worker/`** — a Cloudflare Worker (`ourspace-api`) + D1 database (`ourspace-db`) on the free plan at `https://ourspace-api.ourspace-api.workers.dev`, deployed with `npm run deploy` from `worker/` (needs `npx wrangler login` once; secrets via `wrangler secret put`, all in `worker/README.md`). `Spotify.API` and `Guestbook.API` in `apps.js` point at it; `ALLOWED_ORIGINS` in `worker/wrangler.jsonc` lists the pages allowed to call it (live site, github.io, localhost:8123/8124). The guestbook is live and shared; Top Songs is malten's real list refreshed every 10 minutes by a cron.

## October 22, 2026 — revision pass (read with the October update below)

- **Boot** (`Boot` in `desktop.js`, CSS under "first boot"): EVERY load of `index.html` (`?boot=0` skips it; the inline script adds `body.booting` before first paint) shows a black screen with a beige tower → the power button (or any key / a click on the tower) unlocks audio (`Sfx.degauss` monitor thump, `Sfx.hum` fans + drive spin-up underneath everything) → a typed BIOS/POST screen (`Sfx.post` piezo beep, memory count, `Sfx.floppy` track-0 seek, drive detection with `Sfx.disk` actuator chatter) → a "Malten 98" splash with the scrolling bar → a classic logon dialog ("Welcome to Malten 98", user name `guest` / password `password123`, OK) — silent, like the real one. OK/Cancel/Enter → `finish()`: the overlay fades, the hum fades, `Sfx.startup` (a Windows-98-style chime of our own: detuned Eb pad, rising run, bell, sparkle) plays as the desktop appears, `WM.openOnLoad()` opens the held windows (OurSpace zooms up), `openDeepLink()` runs. `Boot.sound(name, synth)` plays `assets/sfx/<name>.mp3` (`post`, `floppy`, `disk`, `startup`) only for names listed in `Boot.recorded` (empty by default, so the live site never requests a file that isn't there and logs no 404s), else the synth — to use real recordings, drop them in `assets/sfx/` AND add their names to `Boot.recorded`. `Boot.show({auto, skipPost})` re-runs the whole thing in place (after a shutdown): `auto` presses the power button itself, `skipPost` starts at the splash.
- **Shut down** (`Shutdown` in `desktop.js`, `#shutdown` CSS): Start → Shut Down… opens the Win98 dialog (Stand by / Shut down / Restart / Restart in MS-DOS mode; Help → the BSOD, the old easter egg). Shut down: `Sfx.shutdown` (a descending run of the startup chord) over the splash "Malten 98 is shutting down…" while `WM.closeAll()` clears the desktop → "It's now safe to turn off your computer." in orange → `Sfx.crtOff` + the `crt-off` collapse animation → the **breathing standby screen** (`.sd-breathe`, a dark glow pulsing every 5s) until a key, click, touch or a real mouse move (≥12px, listeners armed after 1.2s) → `Boot.show({auto: true})` boots again. Restart: splash → boot. MS-DOS mode: splash → a `C:\MALTEN>` prompt types WIN → boot from the splash. Stand by: breathing screen → the desktop straight back. `body.booting` is on for all of it (desktop hidden, screensaver held off). On blog pages the same dialog works, and waking navigates to `index.html`. `index.html`'s inline script adds `body.booting` before first paint; `body.booting > :not(#boot)` is hidden. Esc or "skip ▸" skips. The usual first-click `tada` greet is suppressed while booting.
- **OurSpace opens at 80% of the desktop**, centred (`data-start-fill="0.8"` → `WM.fill()`, class `.sized`, replaces `data-start-maximized`), so the desktop shows around it. Maximize still works (`.maximized` height is `!important`); below 820px `.sized` means nothing.
- **Navigator chrome on the OurSpace window** (`index.html`): a `.nav-chrome.ms-chrome` strip between the title bar and the body — ◀ Back (`MS.back()`), 🏠 (feed), and an Address bar `#ms-url` that `MS.paintUrl()` (called from `paintTabs`) keeps in step with the page: `http://ourspace.page/feed`, `/you/<name>`, `/malten`, `/<id>/blog`, `/bulletins`, `/inbox/<id>`, `/join` while the sign-up is up, … (`MS.urlFor()`). Title bar now reads "🌐 OurSpace — Maltenscape Navigator".
- **Tabs**: a **Malten's Page** tab (`data-page="profile" data-arg="malten"`) sits between My Page and Blog; tab buttons may carry `data-arg`, and `paintTabs` lights a tab only when page *and* arg match.
- **Feed click-throughs**: feed lines of type `wall` / `bulletin` are `.ms-feedlink`; clicking one calls `MS.goToFeedItem(item)` → the bulletin board (growing the paged list far enough) or the wall it landed on, then `flashKeyed()` finds the card by `data-bkey` / `data-wkey` = `from|time` and `reveal()` scrolls + flashes it (`reveal` is the old tail of `jumpTo`). Every place that creates a wall entry / bulletin plus its feed line now shares one `now()` string so the pair matches.
- **malten's resident data** (`content-src/base/residents/malten.json` → rebuilt pack): age 24, status Taken, here for Nostalgia, the "i only sleep 4 hrs" sentence removed from the about, interests reduced to General only ("video games, poetry, the yard, oddly reminiscent websites of discontinued social medias"). His page's "View My:" row is a single `📁 Blog` button (`.ms-viewblog`); the visitor's My Page gets a big yellow `🎨 Edit My Page` button under the picture (`.ms-editbig`).
- **Typing sound**: choosing a reply in a DM conversation types it out with `Sfx.key(space)` — a band-passed noise burst over a low thunk, a deeper version for the space bar (mechanical-keyboard / Emily-is-Away feel), slightly slower per character.
- **Pipes screensaver**: bigger lattice (pitch = min(W,H)/12, 48–90px; pipe radius = 0.3 × pitch), no joint balls at all — each straight run is redrawn as ONE round-capped stroke from its start to the moving tip, so elbows are just two runs meeting — 20 cells/s, 4–9 pipes, 8 layers. When the lattice is 60% used (or jammed) the occupancy map is forgotten — not the canvas — so new pipes paint over the old ones; after 4 such fills it fades to black and restarts.
- **CRT intensity**: `Toggles.crtLevel` (10–100, localStorage `malten_crt_level`, default 25) sets the `--crt` custom property; `body.crt::after` uses it as opacity (scanlines, glow and flicker scale together). The Control Panel has a "📺 CRT mode" section: an on/off checkbox (kept in step with the tray via the `crt-change` event) and an intensity slider that switches the effect on when dragged.
- **Blog previews** (`.blog-preview img`): the frame takes the picture's own shape (`width:auto; height:80px`) instead of a fixed 110×80 box, so pfp.png (360×301) fills it with no white gutters.
- `.claude/launch.json` has a second config, `static-site-8124` (`http-server -p 8124`), for when 8123 is taken or unwanted.

## How to run

- Just open `index.html` — everything works offline (guestbook local, chiptune demos). **Except YouTube posts:** since 2025 YouTube refuses embeds from pages with no Referer (error 153), so `file://` can't play them — use the dev server (`npx http-server`) or a real host. YouTube also sometimes answers error 150 ("not available here") for a whole network when it suspects bots; it clears on its own, and the player card offers "try again" / "watch on youtube.com".
- Live mode needs nothing: `apps.js` talks to the deployed Worker from localhost too (its origin is allow-listed). To hack on the Worker itself: `cd worker && npm run db:local && npm run dev` (http://127.0.0.1:8787, secrets in the gitignored `worker/.dev.vars`) and point the two `API` constants at it temporarily.
- Dev preview: `.claude/launch.json` defines `static-site` (`npx http-server -c-1 .`, port 8123 with `autoPort` — when something else holds 8123, e.g. Unreal Editor, the app picks the next free port and tells you which) and `static-site-8124` (the same server pinned to port 8124).

## Gotchas

- **Git (Oct 2026 reset)**: history restarted on an orphan branch **`main`** with a root `.gitignore` (node_modules, `.env*`, `*tokens.json`, `db.json`, `*.db`). The pre-rebuild history lives in the local-only branch **`old-master-DO-NOT-PUSH`** — it contains the Spotify client secret, tokens and messages.db, so never push it (`origin` is the public GitHub repo — push only `main`; delete the branch once it's not needed). The Spotify client secret that was in it should be rotated. Root `.env` is a stale leftover from the old root server.js; `spotifyserver/.env` is the live one.
- The API base URL is hardcoded twice in `apps.js` (`Spotify.API`, `Guestbook.API`); `localBackendOk()` only matters for localhost URLs, so a real host is always tried.
- Spotify `preview_url` is often null nowadays (Spotify deprecated previews); Amp shows "no preview" per-track.
- App builder code must use `.window[data-app=…]` selectors — the window divs have no ids.
- Sounds only start after first user interaction (browser autoplay policy).
